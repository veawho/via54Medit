# v2.12.0 — step3 vs step4 相反合并规则 (2026-08-05 用户硬规则)

## 用户原话

> "下载目录不合并，多少个Pn-x，就有多少个子目录"
> "highlight目录需要按照同一文献进行合并"

## 严格相反规则

| 目录 | 合并规则 | 数量 | 命名 |
|------|----------|------|------|
| **step3 下载目录** | **不合并** 1:1 镜像 PPT 标号 | 160 Pn-x | `P{a}-{n}` |
| **step4 highlight 目录** | **按 DOI 合并** | 85 唯一 DOI + 11 无 DOI = 96 | `Pn1-x1Pn2-x2...` (跨标号共享) |

## 为什么相反?

- **step3 是原始下载**: 数据对齐真值, 1 个 Pn-x 必须独立保留才能匹配真值 `citation_table.csv` (160 行)
- **step4 是 highlight 处理**: 同一文献被多个标号引用 (1,2 / 1-3 共享), 黄线只在同一 PDF 上加一次, 合并后避免重复处理

## 实现细节

### step3 不合并 (merge_same_doi_pdfs.py 跳过)

```python
# 错误的合并 (会破坏真值对齐)
if doi == '10.1016/j.annonc.2025.08.2124':
    os.rename('P5-17', 'P5-17P12-1P22-1...')  # ❌ 不要

# 正确: 160 Pn-x 独立保留
for pn in truth_pns:
    os.makedirs(pn)  # ✅
```

### step4 按 DOI 合并 (merge_same_doi_pdfs.py 应用)

```python
# 正确: 按 DOI 聚合
for doi, pns in doi_groups.items():
    if len(pns) > 1:
        new_name = ''.join(f'P{a}-{n}' for a, n in pns)
        for a, n in pns:
            os.rename(f'P{a}-{n}', new_name)  # ✅
```
