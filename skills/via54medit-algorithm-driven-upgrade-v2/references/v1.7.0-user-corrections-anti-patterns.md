## 反模式清单 (绝对禁止)

### ❌ Anti-pattern 1: OPT 装饰性包装 (7 个 OPT 文件)

**症状**: 写 `signatures.py`, `config_validator.py`, `circuit_breaker.py` 等 wrapper, 然后 `from wrapper import ...` 加 try/except 假装集成。

**为什么错**:
- OPT 文件**对实际下载成功率贡献 0%** (测量数据: 7.2% → 100% 完全靠 v13 真接 Chrome, 不靠 OPT)
- 制造"已集成"假象, 让用户以为是真干活, 实则 107 个 unit test 是 theater
- `chrome_batch_pdf_downloader_v15.py` 顶部 8 行 import, `download_and_archive()` 末尾是 `print("would download")` 占位符 — 这不是集成, 是装饰

**正确做法**:
```python
# ✓ 真集成 — 直接 import v13 真干活函数
sys.path.insert(0, '/Users/david/Desktop/test')
from chrome_batch_pdf_downloader_v13 import (
    Tab, DownloadsWatcher, fetch_via_cdp, fetch_via_urllib,
    JS_SCAN, JS_GET_SCIHUB_PDF, verify_pdf_content, save_pdf,
    clean_doi, frontiers_pdf, unpaywall_api, epmc_pdf,
    SCI_HUB_MIRRORS, should_skip_scihub,
)
```

### ❌ Anti-pattern 2: headless-style 抓 PDF

**症状**: 用 `Page.printToPDF`, `Page.captureScreenshot`, `browser_*` 隔离 sandbox, Puppeteer headless。

**为什么错**:
- `Page.printToPDF` 抓的是 HTML 渲染后版本 (Chrome viewer 套 1 页 "ORIENT-…"), 不是真 PDF
- Headless Chrome 100% 被 Cloudflare / Turnstile 拦 (无 history, 无 cookie, 无扩展)
- 我之前 `redownload_all.py` 用 `fetch(window.location.href).blob()` 拿到的是 HTML text, 不是 `application/pdf`

**正确做法**:
```python
# ✓ 真接 Chrome session + Fetch.enable + getResponseBody
tab.send('Fetch.enable', {'patterns':[{'urlPattern':'*','requestStage':'Response'}], 'handleAuthRequests':True})
tab.ws.send(json.dumps({'id':...,'method':'Page.navigate','params':{'url':url}}))
# 等 Fetch.requestPaused → Fetch.getResponseBody → 拦截 response body
# Chrome 拿到的是真 server response, 用自己 session cookies
```

**为什么错**:

**正确做法**:

### ❌ Anti-pattern 4: 拿 HTML 当 PDF

**症状**: `verify_pdf_content` 用 `data[:4] != b'%PDF'` 检查头部, 失败时只说 "not_pdf", 但不去查返回是不是 HTML。

**为什么错**:
- Elsevier / Nature / AACR 在 Cloudflare 拦截时返回 1.2MB Cloudflare HTML challenge
- HTML 头部不是 `%PDF`, 但 size > 100KB, 通过 size check
- `verify_pdf_content` 早期版本因为只看头部, 没去验全文 → 大量假阳性
- 我之前 `redownload_all.py` 看到 "wrong type: text/html" 就放弃, 没 fallback

**正确做法**:
```python
# ✓ 类型严格检查 + 内容验证
if not data or data[:4] != b'%PDF':
    return None, f'not_pdf ({len(data)} bytes, header={data[:30]!r})'

# ✓ 全文 DOI 后缀匹配 (不是只看前 2 页)
r = subprocess.run(['pdftotext', pdf_path, '-'], capture_output=True, text=True, timeout=30)
text = r.stdout.lower()
suffix = doi.lower().split('/')[-1]
if suffix in text:
    return True
```

### ❌ Anti-pattern 5: `data.get('key', {})` 当 value 是 None

**症状**: `data.get('resultList', {}).get('result', [])` — 如果 API 返回 `{"resultList": null}`, 第一步返回 None, 第二步 `None.get(...)` 抛 `AttributeError: 'NoneType' object has no attribute 'get'`。

**真实踩坑** (v13 epmc_pdf, unpaywall_api):
- Europe PMC API 对某些 DOI 返回 `{"resultList": null}` → v13 抛 AttributeError
- Unpaywall API 对无 OA 的论文返回 `"best_oa_location": null` → v13 抛 AttributeError
- 我 v1 跑 84 个 → 12 个 AttributeError → 75% 成功率

**正确做法**:
```python
# ✓ None-safe (用 `or {}` 替代 `, {}` 默认值)
result_list = data.get('resultList') or {}
results = result_list.get('result') or []
oa_locations = data.get('oa_locations') or []  # 不是 [, []]
best = data.get('best_oa_location') or {}
```

### ❌ Anti-pattern 6: 一次 30s 等待 vs 30 轮 1s 轮询

**症状**: `tab.send('Page.navigate'); time.sleep(30); tab.eval(JS_SCAN)` — 单次 sleep 30s, 假设 Unpaywall 30s 内一定注入完成。

**为什么错**:
- Unpaywall content script 是异步加载, 受网络/竞态影响
- 单次 30s 后 Unpaywall 还没注入, iframe.name 仍是空 → 错过
- 30 轮 1s 轮询在 5s 就拿到 color, 后续 25s 浪费但**不会失败**

**正确做法**:
```python
# ✓ 多轮轮询 (30 轮 × 1s = 最长 30s, 通常 5-10s 拿到)
findings = {}
upw_color = None
for attempt in range(30):
    time.sleep(1)
    scan_str = tab.eval(JS_SCAN)
    if scan_str:
        findings = json.loads(scan_str)
        upw_color = findings.get('unpaywall_color')
        if upw_color is not None:
            break
```

## 怎么判断自己的方案是不是 OPT 装饰?

**自我审视 checklist** (写 OPT 前过一遍):

```
□ 1. 我读完了生产代码 (v13) 吗? (ls -lat + cat 全部)
□ 2. 我的新代码调用了生产代码吗? (grep 'from chrome_batch_pdf_downloader_v13 import')
□ 3. 跑真实输入 (84 unique DOIs) 后, 成功率从 X% 提升到 Y%?
□ 4. Y - X 是真的贡献, 还是 unit test 制造的假象?
□ 5. 我有没有用 headless / Page.printToPDF / 隔离 sandbox? (如果用了, 就是错的)
□ 6. 我的 verify 检查是全文 (pdftotext 全跑) 还是只看头部?
□ 7. 我的 None handling 用的是 `or {}` 还是 `, {}`?
```

**任何一项打 ✗, 你的 OPT 就是装饰, 该删。**

## 怎么判断该不该删 OPT 文件?

**症状**:
- OPT 文件在生产路径里找不到调用点 (`grep -r 'from circuit_breaker' .` → 只有 test 文件)
- OPT 文件被 import 但被 except 吞掉 (`try: import X except: pass`)
- OPT 文件加了 type hint / schema / config, 没改运行时行为

**判定**:
- 跑 84 个真实 DOI, 比之前的 baseline 提高 ≥5 pp? → 保留
- 跑 84 个真实 DOI, 没提高? → 删 (这是我的 7 个 OPT 文件的真实命运)

## 核心 takeaway

**用户反复强调的 5 条**:
1. 复现成功结果 (读历史代码, 不要造新 OPT)
2. 真接 Chrome Canary (Cloudflare 100% 拦 headless)
3. 按 4 步顺序 (Unpaywall → Sci-Hub → Google → 标记)
4. Hermes 扩展可以代行人肉点击 (Turnstile / Unpaywall button)
5. 我自己必须意识到错误, 不要让用户骂

**违反任何一条, 用户会立即发现** — 因为他每天都用这套 Chrome session, 哪个 PDF 真能下他心理有数。
