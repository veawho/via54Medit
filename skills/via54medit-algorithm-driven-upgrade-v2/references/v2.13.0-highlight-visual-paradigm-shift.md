# v2.13.0 — Highlight 视觉驱动范式转变 (用户硬规则, 2026-08-05 多次重申)

## 用户原话 (饭喂到嘴边)

> highlight是找PDF中的段落、图表、表格，去证明PPT中对应的视觉意义
> 每个标号只 highlight 自己应证的内容，不共享其他标号关键词
> highlight对象是PDF中的整段、整句、表格、图表，禁止标注单个数字词汇
> highlight样式是黄色系线
> highlight的整段、整句、表格、图表，必须是严格对应PPT视觉的，而不是看到关键词就highlight
> 重新highlight前，要清理已经被highlight过的所有文件，用干净的未被highlight的文件重做
> 视觉理解PPT，将理解内容去PDF导出的每页图片中去比对，比对清楚了先highlight图片，然后将highlight复刻到pdf里
> 视觉解决视觉

## 根本错因 (3 层)

### 第 1 层: 拆 PDF 文字不对
- PyMuPDF `get_text("blocks")` 把一段切成多个 block (一行一段)
- "到 2030 年... 46.6%" 被切成 4 块, 合并逻辑靠 y 坐标阈值, 不准
- **图表/表格/图片用文字块搜索找不到**

### 第 2 层: 关键词评分不对
- 主题词 + 数字评分 = 变相关键词匹配
- page 1 通知头含 "2023" + "2030" + "中国" + "健康" → 评分高但不是 PPT 视觉应证
- **真应证 = 整段逻辑通顺 + 含 PPT 视觉核心数字 % + 含主题**

### 第 3 层: 验证脚本错
- PyMuPDF underline type = `(9, 'Underline')`
- 测试脚本用 `type[0] == 12` → 永远 0
- annotation 抛 "not bound to any page" 没 try/except → 验证脚本崩
- **没真验证 PDF 是否保存 = 跑了等于没跑**

## v2.13.0 正确算法 (用户喂饭式设计)

### 7 步拆开, 算法驱动调度

```
步骤 1: 重置 step4 PDF
  └─ 从 step3 复制干净 PDF, 删旧 highlight PDF + 旧 PNG
  └─ 算法: reset_pnx(pn_key), 跳过有问题的 Pn-x

步骤 2: PDF 每页导 jpg
  └─ PyMuPDF get_pixmap(dpi=120)
  └─ 缓存: step4/Pn-x/_pdf_jpg/page_NNN.jpg
  └─ 算法: render_pdf_pages_to_jpg(pdf_path, out_dir, dpi)

步骤 3: 提 PPT slide jpg
  └─ step1_ppt_目录/_ppt_renders_expanded/slide_NNN.jpg
  └─ PowerPoint 渲染 (不 Keynote/LibreOffice)

步骤 4: 视觉比对 (vision_analyze)
  └─ 输入: PPT slide jpg + PDF page jpg
  └─ 输出: "标号 N 应证段 bbox" (x0, y0, x1, y1) in jpg pixels
  └─ 提问模板: "指出哪些段落/句子/图表/表格能证明 PPT 视觉 X. 给 bbox."

步骤 5: 在 jpg 上画浅黄细线
  └─ PIL.ImageDraw.line([(x0, y1), (x1, y1)], fill=(255, 255, 153), width=2)
  └─ 浅黄 RGB (1.0, 1.0, 0.6) = (255, 255, 153)
  └─ 在 y1 处画 = 文字下方细黄线

步骤 6: 坐标映射 → PyMuPDF
  └─ jpg bbox → PDF pt: scale = pdf_w / jpg_w
  └─ PyMuPDF add_underline_annot(rect)
  └─ color = (1.0, 1.0, 0.6) stroke
  └─ saveIncr() 增量保存; 失败 try save + tmp + move

步骤 7: 验证 + 提最终 PNG
  └─ 重开 PDF, 验证 type[0] == 9 (underline) 数
  └─ extract_page_png(pdf_path, best_page, out)
  └─ 必须每步验证, 不允许"跑了等于没跑"
```

### P3-2 实例 (用户给的范例, PyMuPDF 真实 bbox — 2026-08-05 反思会话更新)

**PPT 视觉** (slide 3 jpg):
- 标号 2 (右上角小角标): 引《健康中国行动》2
- 应证视觉: 中央大字 "到 2030 年我国总体癌症 5 年生存率达到 46.6%"

**PDF 应证段** (page 3) — PyMuPDF 真实坐标:
- 段头 "（二）主要目标。到2030年... 危险": y0=64, y1=79 (段 0)
- 段尾 "存率达到46.6%, 患者疾病负担得到有效控制。": y0=151, y1=165 (段 3)
- **整段 bbox PDF pt = (84, 64, 512, 165)**
- 段被切成 4 个 block (段 0/1/2/3, y0=64-79, 79-108, 122-136, 151-165)
- 转 jpg 像素 (120dpi, × 120/72): **(140, 107, 853, 275)**

**PyMuPDF 真实 bbox 提取代码**:
```python
import fitz
doc = fitz.open(pdf_path)
page = doc[2]  # page 3 (0-indexed)
blocks = page.get_text("blocks")
for b in blocks:
    x0, y0, x1, y1, text = b[0], b[1], b[2], b[3], b[4]
    if '46.6' in text or '主要目标' in text or '患者疾病负担' in text:
        print(f'  段 ({x0:.0f},{y0:.0f})-({x1:.0f},{y1:.0f}) pt: {text[:80]}')
# 整段 bbox = (84, 64, 512, 165) pt = (140, 107, 853, 275) px at 120dpi
```

**用户原话 (饭喂到嘴边)**: "我都把要标注的内容发给你了, 你都highlight不对" — 必须用 PyMuPDF 真实坐标, 不发明未验证的估算 (之前 v10 猜 jpg (40, 80, 1100, 280) 错了, 画到了下方 "二、控制危险因素" 段底)

**完整操作**:
1. vision_analyze PPT slide_003.jpg → 提"标号 2 应证 = 46.6% 政策目标字"
2. PyMuPDF `get_text("blocks")` 提真实 bbox PDF pt (84, 64, 512, 165) — 不靠 vision 猜, 用 PDF 真实坐标
3. PIL 画浅黄细线 on jpg → 保存 preview (在 y=275 处画线, RGB (255, 255, 153))
4. 坐标映射 → PDF pt: scale = 72/120, x0_pt=84, y0_pt=64, x1_pt=512, y1_pt=165
5. PyMuPDF `add_underline_annot(rect=(84, 64, 512, 165))` → `saveIncr()`. **只设 `stroke=(1.0, 1.0, 0.6)`, 不要 `fill` (PyMuPDF Warning "fill color ignored for annot type 'Highlight'")**
6. 验证 PDF underline 数 ≥ 1 (用 safe_annot_type try/except 包装)
7. vision_analyze 看 page_003_highlighted.jpg 自检 — 浅黄细线在 "存率达到46.6%, 患者疾病负担..." 下方 ✅

## 严禁 (19 反幻觉铁律 + 本次新增)

20. **严禁关键词匹配** — 整段/整句/图表/表格, 严格对应 PPT 视觉
21. **严禁标单个数字词汇** — 是整段, 不是词
22. **严禁按段数叠加评分** — 用单段最高分 (含 PPT 视觉核心数字 % + 主题)
23. **严禁 fill 矩形** — 必须 underline 浅黄细线 (add_underline_annot)
24. **严禁不验证** — 每步必须验证保存成功 (annotation type[0] == 9)
25. **严禁"跑了等于没跑"** — 跑完看 PDF underline 数, 没成功标错就重跑
26. **严禁拆 PDF 文字段当应证** — 视觉解决视觉, 用 PDF page jpg vision 配对
27. **复现性**: 一键脚本 + 主函数 highlight_pnx(pn_key), 不能今天跑通明天跑不通
28. **PyMuPDF underline annot 只支持 stroke, 不支持 fill** (用户原话: "浅黄色细线") — `page.add_underline_annot(rect).set_colors(fill=...)` 会被 PyMuPDF Warning 忽略 ("fill color ignored for annot type 'Highlight'"). 只用 stroke=(1.0, 1.0, 0.6) 即可
29. **严禁凭印象猜 bbox** (用户原话: "我都把要标注的内容发给你了, 你都highlight不对") — 应证段 bbox 必须用 PyMuPDF `get_text("blocks")` 提真实 PDF 段坐标 (x0_pt, y0_pt, x1_pt, y1_pt in PDF 72dpi pt 单位). 例: P3-2 应证段 PDF pt = (84, 64, 512, 165), 段被切成 4 个 block (段头 y=64-79, 段尾 y=151-165). 整段 y0 = 段头 y0, y1 = 段尾 y1, x0 = 84, x1 = 512. 不要用 jpg 像素猜 (40, 80, 1100, 280) — 容易错位到上下段
30. **严禁画红框让你确认** (用户原话: "红框又是你的新发明, 你哪来那么多新发明") — 不发明未要求的 UI 元素. 验证靠 vision_analyze 看 PNG 自检
31. **PyMuPDF annotation type 必须用 safe 包装** — `a.type` 抛 "annotation not bound to any page" 时脚本会崩. 必须 `try: if a.type and a.type[0] == 9: ... except: pass`
32. **annotation type 编号不能凭印象** — PyMuPDF underline = 9 (不是 12), highlight = 8, text = 1. 测试验证脚本用错类型编号会让"跑通"变"假跑通"
33. **严禁 `a.type` — PyMuPDF segfault trap** (2026-08-05 反思会话新增) — `page[i].annots()` 返回的 annotation 在 `saveIncr()` 之后 reopen 时, `a.type` 调用会抛 "annotation not bound to any page" (exit -11 segfault, 不是普通异常). **绝对不能 try/except 包住** — `try: a.type` 仍触发 native segfault, Python 没法接住. 必须**完全避开 `a.type`, 用 `a.rect` 维度推断**: `rect.width > 50 and rect.height < 30` = underline; `rect.width < 50` = 不是 underline. verify 脚本必须用此模式, 否则整个脚本 crash 看似"没输出"
34. **严禁让 user 确认 highlight 对错** (用户原话: "你让我确认对不对之前, 为什么不能你自己用视觉检查下" 2026-08-05 反思会话新增) — highlight 跑完**必须自己用 vision_analyze 看 PNG** 或 **PIL+numpy 找浅黄像素位置**验证. 不发明未要求的 UI 元素 (红框/绿色检查线等). 自检脚本: `scripts/verify_highlight_self_check.py` (4 项: PDF underline rect 推断 + jpg y 位置 ±15px + 浅黄颜色 + x 覆盖率 ≥70%)

## Pydantic schema (vision_analyze 输出) — 2026-08-05 反思更新

**bbox 双重表达** (PDF pt 真实坐标 + jpg 像素坐标), 避免猜测:

```python
from pydantic import BaseModel, Field, computed_field
from typing import List, Tuple, Literal

class ProofBBox(BaseModel):
    """vision 配对输出的应证段 bbox"""
    page_num: int = Field(ge=1, description="PDF 页码 (1-indexed)")
    # PDF pt 坐标 (72dpi, 真实 PDF 段坐标, 从 PyMuPDF get_text("blocks") 提)
    bbox_pdf_pt: Tuple[float, float, float, float] = Field(
        description="PDF pt 坐标 (x0, y0, x1, y1) in 72dpi — PyMuPDF 真实坐标"
    )
    # jpg 像素坐标 (120dpi, 用于 PIL 画线)
    bbox_jpg: Tuple[int, int, int, int] = Field(
        description="jpg pixel 坐标 (x0, y0, x1, y1) at 120dpi — PIL 画线"
    )
    proof_text_snippet: str = Field(max_length=200)
    matches_ppt_visual: bool = Field(description="是否严格对应 PPT 视觉")
    visual_reasoning: str = Field(max_length=300, description="为什么严格对应 PPT 视觉")

    @computed_field
    def scale_factor(self) -> float:
        """120dpi jpg / 72dpi pdf = 5/3"""
        return 120 / 72

class HighlightProof(BaseModel):
    """标号 N 的视觉配对结果"""
    pn_key: str = Field(pattern=r"P\d+-\d+")
    proof_pages: List[ProofBBox]
    best_page: int = Field(description="最高分应证页 (1-indexed)")
    best_bbox_pdf_pt: Tuple[float, float, float, float] = Field(
        description="最佳 PDF pt bbox — 必填, PyMuPDF add_underline_annot 用"
    )
    reasoning: str = Field(max_length=500)
```

**关键校验** (Pydantic 自动):
- `bbox_pdf_pt` 必须 ≥ 0
- `bbox_jpg` 必须 ≥ 0
- `matches_ppt_visual` 必须 True (否则不画 underline)
- 不许填"猜的"坐标 — 跑 PyMuPDF `get_text("blocks")` 拿真实 PDF pt 坐标, 再 × 120/72 转 jpg 像素
