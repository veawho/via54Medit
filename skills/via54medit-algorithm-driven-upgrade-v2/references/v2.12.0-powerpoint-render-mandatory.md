# v2.12.0 — PowerPoint 渲染强制默认 (2026-08-05 用户硬规则)

## 用户原话

> "powerpoint 渲染作为默认，原因是keynote和libreoffice打开后视觉和PowerPoint不一致，以PowerPoint为准，并默认必须用PowerPoint渲染"

## 规则

**PowerPoint 渲染作为唯一默认, 强制不 fallback Keynote/LibreOffice**

原因: PPT 原版是 PowerPoint 做的, Keynote 和 LibreOffice 打开后视觉不一致 (字体/布局/颜色都不同). 必须以 PowerPoint 渲染为唯一标准.

## 2026-09-11 用户澄清: 判定标准是**保真**, 不是程序名

用户原话:

> "事实上，我是认为 PowerPoint 渲染出来的图片更符合原版，如果有其他渲染图片并不会改变 PowerPoint 排版与文字的方式也可以集成"

所以线要划在"**会不会重新排版**"上, 而不是"是不是 PowerPoint 这个程序":

| 环节 | 能否换 | 说明 |
| --- | --- | --- |
| PPTX → 画面 (版式/文字) | ❌ 不可换 | 必须 PowerPoint。第三方引擎各自重排 OOXML, 字体/断行/autofit 都会分叉 |
| PowerPoint 产物 → 图片 (栅格化) | ✅ 可以换 | PDF 是固定版式, 栅格化器只解释绘制指令、**不重排**, 因此不改变版式 |

- 首选 PowerPoint **直接出位图** (Windows COM `Slide.Export`), 保真上限最高, 还绕开"PDF 字体未内嵌 → 栅格化替换字形"的风险。
- 走 PDF 时本仓库默认用 PyMuPDF 栅格化, 可选 `RENDER_RASTERIZER=pdftoppm`(**必须 `-cropbox`**)。
  本文件下面那段示例用的就是 `pdftoppm` —— 可见原设计本就允许"PowerPoint 定版式 + 别的工具栅格化"。
- 仍然禁止: LibreOffice / Keynote / WPS / python-pptx / Aspose / Spire / GroupDocs / Syncfusion。
- 完整判定标准与各方案证据: 仓库 `docs/ppt-render-fidelity.md`。

### 2026-09-11 追加: 接入 Microsoft Graph 通道

用户指示"接入 Microsoft Graph 通道"。它由**微软服务端(Office 在线)**渲染, 与桌面版同属微软,
故属合格引擎 —— 但**与桌面版有已知差异**, 所以是**显式选项**而非默认:

```bash
RENDER_ENGINE=graph   # Microsoft Graph 的 ?format=pdf 在线转换; 默认仍是 powerpoint(桌面版)
```

- 实现 `scripts/hl_v3_final/graph_render.py`; 自检 `python3 .../graph_render.py --check`。
- 只做 `PPTX → PDF`(因为官方对 pptx→jpg **只给第一页**), 之后由本地栅格化器出逐页图片。
- 要求: 先把文件上传到 OneDrive/SharePoint(该 API 只作用于 driveItem), 凭据见
  `GRAPH_ACCESS_TOKEN` 或 `GRAPH_TENANT_ID`+`GRAPH_CLIENT_ID`+`GRAPH_CLIENT_SECRET`。
- **没有**"桌面版失败就自动切 Graph"这种事 —— 必须显式指定(宁可报错也不静默换引擎)。

### PowerPoint AppleScript (export_via_powerpoint 函数)

```python
def export_via_powerpoint(pptx_path, out_dir, dpi=120):
    abs_pptx = os.path.abspath(pptx_path)
    pdf_path = os.path.join(out_dir, '_tmp.pdf')
    ascript = f'''
tell application "Microsoft PowerPoint"
    open POSIX file "{abs_pptx}"
    delay 8
    set theDoc to front document
    save theDoc in POSIX file "{pdf_path}" as PDF
    delay 2
    close theDoc saving no
end tell
'''
    r = subprocess.run(['osascript', '-e', ascript], capture_output=True, text=True, timeout=120)
    if r.returncode != 0 or not os.path.exists(pdf_path):
        return None, f'PowerPoint 失败: {r.stderr[:200]}'

    # pdftoppm 转 jpg
    subprocess.run(['pdftoppm', '-jpeg', '-r', str(dpi), pdf_path,
                    os.path.join(out_dir, 'slide')], capture_output=True, text=True, timeout=120)

    # slide-1.jpg → slide_001.jpg
    for f in os.listdir(out_dir):
        if f.startswith('slide-') and f.endswith('.jpg'):
            n = int(f.split('-')[-1].split('.')[0])
            os.rename(f'{out_dir}/{f}', f'{out_dir}/slide_{n:03d}.jpg')
```

### 关键 AppleScript 参数

- `delay 8` (PowerPoint 启动 + 打开 PPT 必须 8 秒)
- `delay 2` (保存 PDF 后 2 秒确保写入)
- `close theDoc saving no` (不保存, 避免污染原 PPT)

## 部署要求

- **必须装 PowerPoint** (macOS): `/Applications/Microsoft PowerPoint.app`
- **必须装 pdftoppm**: `brew install poppler` (一般已装)
- **必须装 osascript**: macOS 自带

## 失败模式

如果 PowerPoint 失败:
- AppleScript 权限不够 → 系统设置 > 隐私 > 自动化, 允许 Hermes/Terminal 控 PowerPoint
- PowerPoint 未启动 → delay 8 秒足够
- 路径含空格 → `os.path.abspath` 转绝对
