## 最佳路径: 双轨方案 (基于 GitHub 研究)

### 轨道 A: 确定性 PPTX 解析 (100% 稳定)

用 `python-pptx` 直接读 PPTX OOXML:

```python
from pptx import Presentation
prs = Presentation('/path/to/expanded.pptx')
for slide_idx, slide in enumerate(prs.slides, 1):
    for shape_idx, sh in enumerate(slide.shapes):
        # 100% 确定性数据
        x = sh.left / 914400   # inch
        y = sh.top / 914400
        w = sh.width / 914400
        h = sh.height / 914400
        text = sh.text_frame.text if sh.has_text_frame else ''
        # 拿到 caption 标注, 引文, 数字 (确定性)
```

**能确定提的字段**:
- 文本内容 (引文, 表格, 标签)
- 对象位置 (坐标, 大小, 旋转)
- slide 编号, shape 层级
- 表格行/列/单元格
- 图片文件名

**不能确定提的字段** (为什么还需要 vision):
- 图片里画了什么 (KM 曲线图, 柱图, 折线图)
- 哪个标号视觉上关联哪个柱图
- 图表视觉含义 (哪些柱代表什么)
- 多个重叠对象的视觉关系

### 轨道 B: Vision 验证 (96.9% 视觉)

保持 v2.7.0 vision 算法, 但**只用于 XML 不能确定的字段**:
- 柱图/KM 曲线的关联数据 (哪些柱对应什么方案)
- Y/X 轴刻度
- 视觉数据点 (数字标签)

### 3 次运行的正确聚合方法

不要对所有字段都简单投票, **按字段类型分类聚合**:

| 字段类型 | 聚合方法 | 例 |
|---------|---------|-----|
| 检测型/召回型 | **取并集** | 发现的标号, 图片元素, 候选引文 |
| 分类型 | **多数投票** | 标号 ③ 属于 A/B/C 哪一个 |
| 坐标型 | **中位数 / IoU 聚类** | 不能对坐标字符串做多数投票 |
| 文本 OCR | **规范化后编辑距离聚类** | "16.43月" vs "16.43 个月" |
| XML 确定的字段 | **不投票, XML 为准** | 引文文本, shape 位置 |
| 3 次全不同 | **不强行选, 标 needs_review** | 人工裁定 |

### v7b: 标号 N → PPTX 哪个 shape 含引文

```python
import re

def find_pptx_for_citation(truth_c, slide_idx, pptx_data):
    """真值 C 字段 (引文) → 找 PPTX 哪个 shape 含这个引文"""
    sd = next((x for x in pptx_data if x['slide'] == slide_idx), None)
    if not sd: return []
    
    # 提真值 C 字段的关键标识 (作者姓 + 年份)
    m = re.search(r'([A-Z][a-zA-Z\-]+)\s+[A-Z]{1,2}', truth_c)
    if not m: return []
    author = m.group(1)
    ym = re.search(r'(20\d{2})', truth_c)
    year = ym.group(1) if ym else None
    
    results = []
    for sh in sd['shapes']:
        text = sh.get('text', '')
        if not text: continue
        if author in text and (not year or year in text):
            results.append({
                'shape_idx': sh['index'],
                'shape_type': sh['type'],
                'x': sh.get('x'), 'y': sh.get('y'),
                'text': text[:200]
            })
    return results
```

**效果**: 138/160 = 86.2% 命中. 漏 22 个全是中文政策/指南/共享引文 (e.g. "原发性肝癌诊疗指南 (2026年版)", "Mellman et al. Immunity 56 (2023)").

## 关键判断: XML vs Vision 冲突时

**XML 不能提的字段** (必须 vision):
- 柱图/KM 曲线的视觉关联
- 图片里画的图形
- 视觉数据点 (柱顶, 标签)

**Vision 误读风险的字段** (XML 优先):
- 引文文本 (XML 100% 准)
- 坐标位置 (XML 100% 准)
- shape 类型 (XML 100% 准)
- 表格单元格内容 (XML 100% 准)

**冲突时优选 XML**, Vision 标 `conflict` 警告.

## 重要: Vision 不稳定根因 + 应对

### 根因

Vision LLM (Gemini/Claude/GPT-4V) 默认 `temperature=0.0` 仍会有 ±3-5% 数字漂移. 真随机性来自:
1. token 采样 (即使 temperature=0)
2. 视觉模型本身对柱图/图表的解码不稳定
3. 图例 vs 柱顶混淆
4. 脚注 vs 主图混淆

### 应对 3 招

1. **XML 主干** (v2.8.0) — 文字/坐标/层级 100% 稳定
2. **N 次跑并集** (v2.7.0) — 漏的减少, 错误保留, 人工校对
3. **JSON Schema 强制** (Pydantic / Instructor) — 输出格式稳定, 但内容仍然不稳

**永远不要把 vision 当唯一解析器**.
