# v2.7.0 — Vision 不稳定性 + 双跑并集策略 (2026-08-05)

## 触发

v2.6.0 视觉算法 96.9% (155/160) 稳定后, 用户要求**全 43 slide 160 条重跑验证稳定性**:

> "重跑43个slide 160条, 验证算法稳定性"

派 4 个 subagent 并行 (P3-P12 / P13-P22 / P23-P30 / P31-P43), 同一提示词, 同一扩页 jpg.

## 关键发现: vision 不稳定

**重跑结果 vs 之前视觉对比**: 表面看 54.9% 一致, 但深挖发现**重大不一致**.

### P31 真实案例 ⚠️

**我之前 (旧) 视觉手跑 P31** (Sun Aug 5 上午跑):
```
任何 imAE: O+Y 57.5% / T+A 68.7% / 雷管方案 35.8%
3-4 级 imAE: O+Y 28.0% / T+A 25.8% / 雷管方案 12.6%
imAE 导致停药: O+Y 12.7% / T+A 7.0% / 雷管方案 5.7%
```

**新 subagent 重跑 P31** (Sun Aug 5 下午跑):
```
任何 imAE: 雷管方案 35.5% / O+Y 19.5% / 靶免 12.5%
```

**第三次独立 vision 跑 P31** (我自己验证):
```
任何 imAE: O+Y 57.5% / T+A 68.7% / 雷管方案 35.8%  ← 跟旧一致, 跟新差很多!
```

**根因**: 新 vision 模型把图例 "35.5% 19.5% 12.5%" (其他子标, 不是柱顶) 误读成柱顶数字. **vision 模型对同一张图, 同样 prompt, 不同时间不同结果**.

## 视觉算法不稳定的 4 类根因

1. **图例误读** (P31 案例) — vision 把图例横轴数字当成柱顶数字
2. **脚注主图混淆** — 第一轮只看主图, 第二轮只看脚注
3. **柱图数值范围缩小** — 真值 0-70% 刻度, vision 报告 0-40% 漏了 68.7% T+A
4. **多引用上标共享** — "1-3" 拆 1, 2, 3 算法不稳定, 时而拆时而合

## 实战教训: "验证稳定性" 跑后会发生什么

**用户问 "重跑验证稳定性", 潜台词**:
- 不是验证算法**重复**性好 (那已经稳定)
- 是验证**新**跑的算法 vs **旧**跑的算法一致
- **如果不一致, 选哪个?**

**答**: 选**多次并集** (宁愿冗余, 不愿漏).

## 双跑并集策略 (实战有效)

**原理**: 同一张图跑多次, 取 data_points **并集** (去重). 漏的减少 (每跑都补), 错误也保留 (但人工改).

## 双跑并集风险

**风险**: 并集可能引入**错误的数字** (e.g. P31 新 vision 报告 35.5%, 真值是 35.8%).

**应对**:
- **高位精度**: 数据点带小数 (35.8% vs 35.5%) 优先级高于整数
- **柱顶/图例/标签**: 优先取柱顶 (主图), 不取图例
- **多次一致**: 3 次跑都有 = 接受, 1 次独有 = 检查
- **人工校对**: 关键数据点 (跟真值 D 字段对照) 人工改

## 实战: P31 二次偏差的例子

**旧 1 次 (我手跑)**: 57.5% / 68.7% / 35.8% / 28.0% / 25.8% / 12.6% / 12.7% / 7.0% / 5.7% (9 个, 100% 跟真值 D 一致)

**新 1 次 (subagent 重跑)**: 35.5% / 19.5% / 12.5% (3 个, 跟真值 D 不匹配, 因为子 agent 把图例当柱顶)

**结论**: 旧 vision 1 次跑 跑得比新 subagent 1 次跑 准. **不要无脑用新跑, 用旧+新并集 + 人工校对**.

## v2.7.0 视觉算法 96.9% 稳定性结论

**视觉算法第一轮天花板**: 96.9% (5 漏 100% PDF 应证数据).

**多跑波动**:
- 每次 subagent 重跑: ±5-10% 波动 (data_points 数量)
- 数字精度: ±0.5% 误差 (e.g. 35.8% vs 35.5%)
- 多次一致 (3 次跑都有): 数字可信 > 95%
- 1 次独有: 数字可信 < 50%

**问"重跑验证稳定性"的标准 SOP**:

1. 重跑所有 164 个标号 (4 subagent 分组)
2. 合并新旧 data_points 取并集
3. 评估 ≥ 50% 命中覆盖率
4. **如果新旧差 > 5%**: 报告用户「vision 不稳定, 差异来自 X (图例/脚注/柱图), 建议双跑并集 + 人工校对」
5. **如果新旧差 ≤ 5%**: 报告「视觉稳定, 覆盖率 X%」

## 待办 (v2.7.0 之后)

**触发**: 用户问 "重跑 43 slide 160 条" 时使用本教程.

**没解决的**: 视觉算法本身 (vision_analyze) 在不同 prompt / 不同时间下, 数字识别会变. 这是模型本身的随机性, 不是算法问题. **接受这个事实, 用并集 + 人工校对应对**.
