# v2.5.0 — 子 agent vision JSON 6 种格式兼容 (2026-08-05 实战坑)

## 根因

子 agent `delegate_task` 并行 vision_analyze 后输出 JSON, **不同 subagent 输出结构不一致**. 合并时如果假设统一格式, 大部分数据点丢失.

## 6 种结构 (实战遇到)

### 1 类: `{slide_N: {mark_N: {...}}}` dict of dict

```json
{
  "12": {
    "1": {"position": "左框", "shape_type": "KM", "data_points": ["16.43月"], "context": "...", "related_visual": "..."},
    "2": {...}
  }
}
```

**处理**: 直接展开 dict.

### 2 类: `[{slide: N, img: ..., marks_observed: [...]}]` list of dicts

```json
[
  {"slide": 31, "img": "slide_031.jpg", "marks_observed": [
    {"mark": 3, "position": {"x_c": 6.76, "y_c": 1.61}, "shape_type": "...", "data_points": ["70.0%"], "context": "...", "related_visual": "..."}
  ]},
  {"slide": 32, ...}
]
```

**处理**: 遍历 list, 每个 item 的 marks_observed 提取.

```python
for item in d:
    if not isinstance(item, dict): continue
    s = str(item.get('slide', ''))
    marks = item.get('marks_observed', [])
    for m in marks:
        n = str(m.get('mark', ''))
        pos = m.get('position', {})
        pos_str = f"x={pos.get('x_c', 0):.1f}, y={pos.get('y_c', 0):.1f}" if isinstance(pos, dict) else str(pos)[:80]
        all_v[s][n] = {
            'position': pos_str,
            'shape_type': m.get('shape_type', '?'),
            'data_points': m.get('data_points', []),
            'context': m.get('context', '?'),
            'related_visual': m.get('related_visual', '?')
        }
```

### 3 类: `{slide_N: "散文", P26: "...", ...}` str values (子 agent 退化)

```json
{
  "_meta": "vision_analyze P26 + P27...",
  "P26": "常见一线免疫联合方案3-4级TRAE发生率超40%, 相关停药率20%左右...",
  "P27": "常见一线免疫联合方案肝毒性事件亟需关注..."
}
```

**处理**: ⚠️ **这格式不可用**, 必须 subagent 重跑 + 强制 JSON 输出.

### 4 类: `{marks: [{mark, all_numbers_on_ppt: [{value, unit, context}]}]}` (P5 格式)

```json
{
  "slide": 5,
  "marks": [
    {"mark": 15, "row_in_table": "R12", "scheme_name": "O+Y", "trial": "CheckMate-9DW",
     "all_numbers_on_ppt": [
       {"value": "4", "unit": "次", "context": "伊匹木单抗诱导次数"},
       {"value": "52.5", "unit": "个月", "context": "随访时间"},
       {"value": "40", "unit": "%", "context": "3/4 级 TRAE"}
     ],
     "truth_D_citation": "Yau T, et al. Lancet 2025...",
     "truth_D_doi": "10.1016/S0140-6736(25)00403-9"
    }
  ]
}
```

**处理**: `value + unit` 拼成 data_points.

```python
marks_list = d.get('marks', [])
for m in marks_list:
    n = str(m.get('mark', ''))
    all_nums = m.get('all_numbers_on_ppt', [])
    dps = []
    for num_info in all_nums:
        if isinstance(num_info, dict):
            v = num_info.get('value', '')
            u = num_info.get('unit', '')
            if v:
                dps.append(f'{v}{u}' if u else str(v))
    result[s][n] = {
        'position': m.get('row_in_table', '?'),
        'data_points': dps,
        'context': m.get('scheme_name', '?'),
        'related_visual': f"Trial: {m.get('trial', '?')}"
    }
```

### 5 类: `{slide_N: {mark_1_3_5_specific_data_points_summary: {mark_N: {attached_data_points: [{where, units: [...]}]}}}}` (P4 格式)

```json
{
  "slide": 4,
  "mark_1_3_5_specific_data_points_summary": {
    "mark_1": {
      "superscript_positions_count": 3,
      "attached_data_points": [
        {"where": "card_1_右上角_1,2", "units": ["80%", "23%", "10%"]},
        {"where": "card_2_末尾_1-3", "units": ["87.3%", "3 cm", "6.7 cm", "35%"]}
      ]
    }
  }
}
```

**处理**: 遍历 `mark_N_specific_data_points_summary`, 提取 `attached_data_points[].units`.

### 6 类: 顶层 `mark_N: {position, shape_type, data_points, context, related_visual}` (P26/27 简版)

```json
{
  "_meta": "...",
  "P26_#1": {"position": "左柱图 IMbrave150 下方", "shape_type": "柱图", "data_points": ["43%", "22%"], "context": "...", "related_visual": "..."},
  "P26_#2": {...}
}
```

**处理**: key 格式 `P26_#N` → slide=26, mark=N.

```python
for k, v in d.items():
    m = re.match(r'P(\d+)_#?(\d+)', k)
    if not m: continue
    s, n = m.group(1), m.group(2)
    if isinstance(v, dict):
        all_v[s][n] = {
            'position': v.get('position', '?'),
            'shape_type': v.get('shape_type', '?'),
            'data_points': v.get('data_points', []),
            'context': v.get('context', '?'),
            'related_visual': v.get('related_visual', '?')
        }
```

## 实战坑 (2026-08-05 踩到的)

### 坑 1: 假设统一格式, 5 个 JSON 只合并 1 个

**根因**: 第一版合并脚本假设 `dict of dict`, 但 P26/27 JSON 是 `{P26: "散文"}` 格式, 全部跳过.

**修法**: 6 种结构分别检测, 兼容 fallback.

### 坑 2: 散文格式 (3 类) 不可用

**根因**: 子 agent vision_analyze 输出自然语言散文, 不是 JSON. 合并脚本无法解析.

**修法**: subagent prompt 强制要求 JSON 输出:

```python
"输出必须是 JSON 格式: {slide_N: {mark_N: {position, shape_type, data_points, context, related_visual}}}"
```

### 坑 3: `all_numbers_on_ppt` 是 list of dicts (4 类)

**根因**: P5 JSON 的 data_points 是 `[{"value": "52.5", "unit": "个月", "context": "..."}]` 不是字符串 list.

**修法**: 遍历 list, 提取 value + unit 拼成字符串.

### 坑 4: P26/27 key 格式 `P26_#1` (6 类)

**根因**: subagent 用 `P26_#1` 作为 key 而不是嵌套 dict.

**修法**: regex 解析 key, 提取 slide + mark.

## 子 agent prompt 模板 (确保 JSON 输出)

```python
"用 vision_analyze 看 PPT 第 N 页 (扩页版). \
列 PPT 上**所有数字+单位** (含柱状图/饼图/标签/脚注/分母/Y 轴/X 轴/风险人数). \
写 {position, shape_type, data_points (含纯数字 '6.47月'/'10%'/'45%'), context, related_visual}. \
输出必须是 JSON: {slide_N: {mark_N: {position, shape_type, data_points, context, related_visual}}}. \
**不允许输出散文/字符串**, 必须结构化 JSON. \
**data_points 必须同时含纯数字和长字符串**: 'OS率 一线 100%' + '100%'."
```

## 教训

**不要假设 subagent 输出统一格式**. 必须:
1. subagent prompt 强制 JSON 输出 + 具体 schema
2. 合并脚本兼容 6 种结构
3. 遇到 3 类 (散文) 必 subagent 重跑
4. 合并后**人工验证覆盖率涨了**, 没涨说明合并脚本漏了一种结构
