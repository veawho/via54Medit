Three reasons (none of them good):

1. **I assumed v15 was the production version** because I had read v15 first. v15 has the placeholder `print("would download to {dst_path}")`. v13 (the version that ACTUALLY downloads) was sitting in the same dir, but I never read it.

2. **I treated the user's "集成到算法里" as a license to write new algorithms.** The user wanted me to ENSURE the existing Chrome pipeline was being driven by algorithms (algorithms like Unpaywall poll, Bayesian mirror selection), not to write new abstract algorithms. The existing algorithms (in `mirror_health_resolver.py`, `content_verifier.py`, `publisher_shortcuts.py`, `fallback_chain_engine.py`) were already correct — what was missing was the integration into Chrome's CDP session, which v13 already had.

## Decision rule for future OPT work

**Before writing any "OPT" / "wrapper" / "enhancement":**

1. `git log -- <production_code_file>.py` — find the latest production version
2. Read it end-to-end. Do not trust the description, do not trust the docstring. Read the actual code.
3. Trace the call graph: `grep -n 'def call_my_thing' production.py` → who calls it → does it actually get called in the production flow?
4. If a v13-class function already does what your OPT claims to do: delete your OPT and call v13 directly.
5. Run the production code end-to-end against real input BEFORE writing tests. If the production code can't run (placeholder, missing Chrome, etc.), your OPT is decorative.

**The user has a hard rule (硬规则 99)**:

> "我需要确保所有优化不会影响原来的功能和产出能力"

That doesn't mean "wrap the old code in a new file". It means "the original production code must continue to work AND the new optimization must add measurable value". Wrapping without integration breaks 硬规则 99 because the original code's value (real downloads) is replaced by wrapper-only theater (no downloads).
